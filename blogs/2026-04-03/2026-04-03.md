# 스프레드 연산자는 콜스택을 활용한다

> tl;dr: `...` 스프레드 연산자는 내부적으로 모든 요소를 콜스택에 올립니다. 그래서 스프레드 대신에 `concat` 메서드를 사용합시다.

- 자바스크립트 내부적으로 `Function.apply`를 사용한다고 합니다. 이 정확한 구현은 부분은 더 조사가 필요합니다.
  - 아마 부스트래핑한 ES 버전이 어디에 존재할 것 같습니다.
  - 높은 확률로 원소별로 함수를 호출하고 다음 원소가 없으면 반환하는 그런 로직으로 작성 되어있을 것이라고 생각 됩니다.

## 사건의 발단

```ts
const detailRows = computed(() => {
  const allRows: Row[] = [];

  for (const query of severityQueries.value) {
    if (query.isSuccess && query.data) {
      allRows.push(...query.data); // 범인이 되는 코드
    }
  }

  if (!reasonCodeFilter.value.length) return allRows;

  const rcSet = new Set(reasonCodeFilter.value);

  return allRows.filter((row) => rcSet.has(row.reason_code));
});
```

- 이런 코드가 `Maximum call stack size exceeded` 에러를 발생시켰습니다.
  - 이런 에러는 함수의 depth가 너무 깊어져서 발생하는 에러입니다. 보통 재귀를 활용할 때 주로 발생합니다.
- 회사에서 표를 다루는 경우가 많고 표의 데이터가 만단위 데이터는 금방 넘어갑니다. 어떤 경우에는 100만 단위도 쉽게 넘어갑니다. 하지만 이렇게 높은 단위의 데이터를 갖는 경우 로직 자체보다 데이터를 감당할 수 있는 클라이언트 용량의 한계 아니면 브라우저의 한계가 더 많습니다. 또 지금의 예시의 경우 처리하고 있던 데이터는 24만개의 객체를 담은 배열입니다. 표랑 관련된 라이브러리가 이것도 처리 못하지 않았습니다. 오히려 더 큰 단위도 잘 처리했습니다. 표랑 관련된 라이브러리는 오히려 소거하는 것이 적합했습니다.
- 이외 의심해본 방향은 반응성이 재귀적으로 발생한 것이라고 추측을 했었는데 아니었습니다.
  - `computed` 내에서 watch 비슷하게 할당 로직을 처리하는 것이 없었습니다. 반응성을 갖고 또 반응하도록 만들어낸 것이 없었습니다.
  - 반응성의 연쇄도 발생하지 않았습니다. 이런 이유로 watch 체인은 소거할 수 있었습니다.
- 실제 이 에러는 해결한 방법이 프롬프트로 해결한 것입니다. 하지만 평소랑 다른 해결법은 에러가 발생하는 지점(브라우저 콘솔 메시지 복사), 에러 메시지, API 응답 데이터 사이즈 이 3가지를 컨텍스트에 추가하니까 스프레드 연산자가 문제라는 것을 찾아냈습니다.

## 해결

```ts
// concat 사용: spread(...)는 대량 데이터에서 콜 스택 초과 발생
const detailRows = computed(() => {
  let allRows: Row[] = [];

  for (const query of severityQueries.value) {
    if (query.isSuccess && query.data) {
      allRows = allRows.concat(toRaw(query.data)); // 해결
    }
  }

  if (!reasonCodeFilter.value.length) return allRows;

  const rcSet = new Set(reasonCodeFilter.value);

  return allRows.filter((row) => rcSet.has(row.reason_code));
});
```

- 위는 문제를 해결한 코드입니다. `let`을 사용한다는 것은 마음에 안들지만 해결한 코드가 맞습니다.
- `push(...spread)` → `concat()`으로 변경. `concat`은 콜 스택을 사용하지 않고 새 배열을 생성하므로 데이터 크기에 제한이 없다고 합니다. 이것에 대한 내부 구현도 찾아봐야 합니다. ~~V8 엔진을 뒤저볼 자신이 없습니다.~~
- 여기서 추가 의문은 콜스택 활용여부를 어떻게 알 수 있는가? 이런 내부동작을 가졌을 것이라는 것은 어디서 알아낸 것인가? 커뮤니티 글이 아니라 자바스크립트 표준 혹은 엔진 소스코드로 알아야 할 것 같은데 알 수 있는 부분인가?
- https://ecma-international.org/publications-and-standards/standards/ecma-262/
- 여기서 표준 찾아 삼만리하면 해당하는 표준들을 찾을 수 있을 것입니다.
- 참고로 스택의 사이즈는 의도적으로 표준을 정하지 않았다고 합니다. 자바스크립트가 실행되는 환경마다 각각 독립적으로 다른 사이즈가 필요할 것이 때문입니다.
- `Function.apply`를 내부적으로 사용하고 있다는 것은 어떻게 알 수 있는가?
  - 재귀 비슷하게 원소를 순서대로 콜스택에 올리는 구현이 되어 있는가?
  - 트랜스파일러는 스프레드 연산자인지 `concat`인지 각각 다르게 변환처리할 것인가?

## 교훈

- 여러가지 교훈
  - 복사는 `concat`을 우선으로 합시다.
- 개발자의 디테일 자체가 하나의 능력이라고 봅니다.
